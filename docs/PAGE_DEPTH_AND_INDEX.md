# Глубина страниц и накопление индекса

## Текущая модель (v5 + deep pages)

1. Yandex Search — только **находит URL** и даёт стартовый passage.
2. `enrich_sources_deep` — для каждого из топ-8 URL:
   - скачивает до **80 000** символов текста;
   - режет на чанки ~900 символов;
   - выбирает **4–5** чанков с максимальным совпадением с запросом (для финансов — бонус за цифры и годы).
3. `extract` (YandexGPT) — JSON-факты из чанков.
4. `answer` — только из FactPack.

Сниппет поиска **не заменяет** страницу, а дополняет её.

## Свой индекс (поэтапно)

### Уровень 0 — без индекса (сейчас)

Live fetch при каждом запросе. Плюсы: всегда свежо. Минусы: latency, JS-сайты, лимиты.

### Уровень 1 — кэш URL (1–2 недели)

Таблица `page_cache(url, fetched_at, text_hash, content_text)`:

- после успешного fetch писать в Redis/Postgres;
- TTL 24–72 ч для новостей, 7 дней для справочников;
- при повторном запросе — чанкить из кэша.

Объём: топ-10k URL ≈ несколько GB текста (сжатие zstd).

### Уровень 2 — индекс «вопрос → URL»

Таблица `query_url_log(normalized_query, url, score, hit_count)`:

- после каждого удачного ответа сохранять пары query+url с высоким retrieval;
- при похожем запросе — **сначала** подмешивать эти URL в search (bootstrap), потом Yandex Search.

Это не полнотекстовый индекс, а **память сервиса** на ваших пользователях.

### Уровень 3 — чанки + эмбеддинги (Yandex Cloud)

Для закэшированных страниц:

- нарезка чанков;
- `text-search-doc` / Embeddings API Yandex;
- хранение в PostgreSQL + pgvector или Qdrant;
- retrieval: embedding запроса → top-20 чанков → extract/answer.

Yandex Search остаётся **источником новых URL**, индекс — **глубина по уже виденным страницам**.

### Уровень 4 — краулер (месяцы)

Отдельный worker: очередь URL из search/log, robots.txt, rate limit. Нужен только при масштабе Perplexity-like.

## Рекомендация для Glosix

1. Сейчас: **deep fetch + чанки** (внедрено в `page_depth.py`).
2. Следующий шаг: **page_cache** в Redis (TTL 48h).
3. Потом: **pgvector + Yandex embeddings** для чанков из кэша.
4. Полный краулер — только при >10k DAU и бюджете на хранение.
