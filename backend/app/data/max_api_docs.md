# MAX Bot API — Документация (platform-api.max.ru)

> Источник: https://dev.max.ru/docs-api  
> Актуально: июнь 2026

---

## Общее

- Базовый URL: `https://platform-api.max.ru`
- Авторизация: заголовок `Authorization: {access_token}` (query-параметры **не поддерживаются**)
- Лимит: не более **30 rps** на один токен
- Формат ответа: JSON
- Начиная с **июня 2026**: метод `GET /chats` не поддерживается; вместо него — `POST /subscriptions`
- С **25 мая 2026**: webhook работает только по HTTPS с сертификатом от доверенного CA

### HTTP-коды

| Код | Значение |
|-----|---------|
| 200 | Успех |
| 400 | Неверный запрос |
| 401 | Ошибка авторизации |
| 404 | Ресурс не найден |
| 405 | Метод не допускается |
| 429 | Превышен лимит запросов |
| 503 | Сервис недоступен |

## Методы

### GET /me — Информация о боте

Возвращает данные о боте: id, имя, username, описание, команды.

**Ответ:** `user_id`, `first_name`, `username`, `is_bot`, `last_activity_time`, `description`, `avatar_url`, `commands[]`

---

### POST /messages — Отправить сообщение

Отправляет сообщение пользователю или в чат.

**Параметры запроса:**
- `user_id` (integer, опц.) — ID пользователя для личного сообщения
- `chat_id` (integer, опц.) — ID чата/группы/канала

**Тело запроса:**
- `text` (string, до 4000 символов) — текст сообщения
- `attachments` (array) — вложения (клавиатура, медиа, файлы)
- `notify` (boolean, по умолчанию `true`) — уведомлять участников
- `format` (`"markdown"` | `"html"`) — форматирование текста
- `link` (object) — ссылка на другое сообщение

**Форматирование (markdown):** `**жирный**`, `_курсив_`, `` `код` ``, `~~зачёркнутый~~`, `++подчёркнутый~~`, `[текст](url)`, `> цитата`, `# заголовок`, `^^выделенный^^`

**Вложения — типы:**
- `inline_keyboard` — кнопки под сообщением (до 210 кнопок, 30 рядов, 7 кнопок в ряду)
- Типы кнопок: `callback`, `link`, `request_contact`, `request_geo_location`, `open_app`, `message`, `clipboard`

**Ответ:** объект `Message`

---

### GET /messages — Получить сообщения

**Параметры:**
- `chat_id` — сообщения из чата (в обратном порядке)
- `message_ids` — конкретные сообщения по ID
- `from`, `to` — временной диапазон (Unix timestamp)
- `count` (1-100, по умолчанию 50)

---

### DELETE /messages — Удалить сообщение

**Параметры:** `message_id` (string)  
Требует права на удаление сообщений у бота.

---

### GET /chats/{chatId} — Информация о чате/канале

**Параметры:** `chatId` (integer)

**Ответ:** `chat_id`, `type` (`chat`/`channel`/`dialog`), `status` (`active`/`removed`/`left`/`closed`), `title`, `participants_count`, `is_public`, `link`, `description`, `owner_id`, `pinned_message`

Статус `active` — бот в чате; `removed` — бот удалён; `left` — бот вышел.

---

### GET /chats/{chatId}/members — Участники чата

Возвращает список участников. **Бот должен быть администратором**.

**Параметры:**
- `chatId` (integer)
- `user_ids` (array, опц.) — конкретные пользователи
- `count` (1-100, по умолчанию 20)
- `marker` — пагинация

**Ответ:** `members[]` (ChatMember с полями `is_admin`, `is_owner`, `is_bot`, `permissions`), `marker`

**Как проверить, является ли бот админом:**
1. `GET /me` → получить `user_id` бота
2. `GET /chats/{chatId}/members?user_ids={bot_user_id}` → проверить `is_admin` или `is_owner`

---

### POST /chats/{chatId}/actions — Действие бота в чате

**Параметры:** `chatId`  
**Тело:** `action` — `"typing_on"`, `"sending_photo"`, `"sending_video"`, `"sending_audio"`, `"sending_file"`

---

### GET /chats/{link} — Получить chat_id по ссылке

Синхронно получает `chat_id` канала по его публичной ссылке (например, `max.ru/-channelname`).

---

### POST /subscriptions — Webhook / подписка на события

Настраивает получение событий через Webhook.

**Тело:**
- `url` (string) — HTTPS endpoint бота
- `update_types` (array) — типы событий, например `["message_created", "bot_started"]`
- `secret` (string, опц.) — секрет для заголовка `X-Max-Bot-Api-Secret`

Webhook работает только по HTTPS с валидным сертификатом. Таймаут ответа — 30 сек. До 10 повторных попыток с экспоненциальным интервалом. Если 8 часов нет ответа — бот отписывается автоматически.

---

## События (Update types)

| Событие | Описание |
|---------|---------|
| `bot_started` | Пользователь открыл диалог с ботом (`/start`) |
| `bot_added` | Бот добавлен в групповой чат |
| `bot_removed` | Бот удалён из группового чата |
| `message_created` | Создано новое сообщение (в DM или группе) |
| `message_callback` | Нажата callback-кнопка |
| `message_edited` | Сообщение отредактировано |
| `message_removed` | Сообщение удалено |
| `user_added` | Пользователь добавлен в чат |
| `user_removed` | Пользователь удалён из чата |
| `chat_title_changed` | Изменено название чата |

Каждое событие в объекте Update содержит: `update_type`, `timestamp`, тело события (с `chat_id`, `user`, `message` и т.п.)

---

## Получение chat_id

| Объект | Способ |
|--------|--------|
| Групповой чат | Через событие `bot_added` или `bot_started` в объекте Update |
| Канал | Через событие ИЛИ через `GET /chats/{link}` по публичной ссылке |
| Диалог (личка) | Через событие `bot_started` — поле `user.user_id` |

## Возможности бота в зависимости от прав

### В личном чате (DM)
- Отправлять сообщения: **всегда** (если пользователь начал диалог)
- Читать сообщения пользователя: **всегда** (через webhook)
- Отправлять файлы, изображения, кнопки: **всегда**

### В групповом чате — обычный участник
- Отправлять сообщения: **да**
- Читать сообщения: **нет** (без прав администратора webhook не отдаёт сообщения из групп обычным ботам)
- Удалять сообщения: **нет**
- Получать список участников: **нет**

### В групповом чате — **администратор**
- Отправлять сообщения: **да**
- Читать все сообщения: **да** (webhook доставляет все события)
- Удалять сообщения: **да**
- Получать список участников (`GET /chats/{chatId}/members`): **да**
- Проверять права других участников: **да**

## Медиафайлы и вложения

Типы вложений в сообщениях:
- `image` — изображение
- `video` — видео
- `audio` — аудио
- `file` — произвольный файл
- `sticker` — стикер
- `inline_keyboard` — кнопки
- `contact` — контакт пользователя
- `location` — геопозиция

Для отправки медиафайлов нужно сначала загрузить файл через API и получить `token` или `file_id`, затем использовать его в `attachments`.

## Ограничения

| Параметр | Лимит |
|---------|-------|
| Текст сообщения | до 4000 символов |
| Описание бота | до 16 000 символов |
| Кнопок на сообщение | до 210 (30 рядов × 7) |
| Команд бота | до 32 |
| Запросов к API | 30 rps |
| Таймаут webhook | 30 сек |
| Повторных попыток webhook | до 10 |
| Перерыв до отписки при недоступном webhook | 8 часов |

## Что умеет бот в MAX — итог

**Всегда (без прав админа):**
- Отправлять текст, файлы, изображения, кнопки пользователю в личку
- Получать сообщения от пользователя в личке через webhook
- Отправлять сообщения в группу (если добавлен)
- Реагировать на команды в личке

**Только если бот — **администратор** в группе:**
- Читать все сообщения группы через webhook
- Удалять сообщения нарушителей
- Получать список участников и их права
- Полноценная модерация

**НЕ поддерживается:**
- Интеграции с другими мессенджерами (Telegram, WhatsApp, VK)
- Отправка email
- Push-уведомления вне MAX
- Работа с внешними CRM/ERP напрямую через бота
- Создание/удаление чатов ботом
- Изменение прав участников ботом
